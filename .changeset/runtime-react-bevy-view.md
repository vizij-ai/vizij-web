The provider binds one `@vizij/runtime` 6 face to a React tree and hands out its `Runtime` unwrapped; the package adds only React plumbing. `@vizij/runtime` (`^6.1.1`) and `@vizij/render` are peer dependencies, and it has no other dependency.

- `<VizijRuntimeProvider glb vizijId? options? run?>` fetches the GLB (a URL, a `Blob` or bytes), reads it with `describe`, waits for the page's `<VizijCanvas>`, loads the face with `loadVizij` and steps its device: once per animation frame while the page is visible, and on a timer while it is hidden, which the timer keeps doing until the first frame after the page returns (`run={false}` leaves stepping to the page). A new `glb` reloads the face in place; unmounting stops, unloads and disposes it. It replaces the `assetBundle`, `namespace`, `autostart`, `driveRuntime`, `stepHz`, `mergeStrategy`, `updateTier`, `transformOutputWrite` and `onRegisterControllers` props.
- `useVizijRuntime()` returns `{ vizijId, status, error, behaviorError, runtime, description }`: `status` is `loading`, `ready` or `error`; `runtime` is `@vizij/runtime`'s `Runtime`; `description` is `describe(glb)`. Every device operation — `setValue`, `writeValues`, `readValues`, `invoke` (skills, programs, animations, `reset`), `halt`, `listKeys` — is called on `runtime`.
- `useVizijValues(paths)` and `useVizijChanges(listener)` read the store's changes, which the provider drains as the one caller of `drainChanges`: once per animation frame while one of them listens, and not at all otherwise. The runtime holds what is not drained as the latest value per key, so a batch is the net change since the previous drain.
- `useAnimateValue()` returns `{ animateValue(path, target, options), cancelAnimation(path) }`: a JS tween in the numeric kind the key holds, or rests at before anything writes it.
- `<VizijRuntimeFace>` is `@vizij/render`'s `<Vizij>` slot bound to the provider's face.
- Removed with the three.js renderer: the value mirror into the render store, the JS graph composer (`composeGraphSpecs`, `collectInputPathMap`, `resolveAnimationBridgeOutputPaths`), the bundle extraction and merge, neutral staging, the `namespace/` prefix, the guest-module loader, the JS clip pipeline and the animation and program calls on the context, `setInput`, `getValueSnapshot`, `subscribeToStep`, `registerInputDriver`, `useVizijOutputs`, `useRigInput`, `resolveRuntimeUpdatePlan`, the face-control and pose-path helpers, and the `VizijAssetBundle` types. `DESIGN-1.0.md` maps each to its replacement.
